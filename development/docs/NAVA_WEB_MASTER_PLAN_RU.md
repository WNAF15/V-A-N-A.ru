## 1. Назначение

NAVA Web — самостоятельная веб-подсистема экосистемы NAVA: аккаунты, общение, сообщество, приложения и в перспективе безопасное управление устройствами и синхронизация с Desktop/Mobile. Разработка продолжает существующий PHP/MySQL сайт, без миграции на другой стек и без подключения Desktop к production.

## 2. Архитектура, подтверждённая по исходникам

- PHP-приложение с собственным MVC-подобным разделением Controllers / Models / Core / Views.
- Собственный Router с регистрацией GET/POST маршрутов.
- PDO/MySQL через `app/Core/Database.php`, prepared statements и отключённые emulated prepares.
- PHP Sessions через `app/Core/Auth.php`.
- Маршруты разделены на `app/Routes/web.php` и `app/Routes/api.php`.
- Чат реализован в `ChatController`, моделях Chat/Message/MessageAttachment и API-маршрутах.
- Хранилище вложений имеет локальную реализацию и S3-совместимый сервис; runtime конфигурация расположена в `app/Config/storage.php`.
- Публичная точка входа: `public/index.php`.
- В репозитории также есть игровые ресурсы; их структура и маршрутизация должны оставаться совместимыми.

## 4. WEB-0 — безопасность и фундамент

| Требование | Статус | Примечание |
|---|---|---|
| Удалить встроенные DB credentials из активной конфигурации | ГОТОВО В КОДЕ | `database.php` читает DB_HOST/DB_NAME/DB_USER/DB_PASSWORD |
| Загрузка приватного .env без зависимости | ГОТОВО В КОДЕ | Добавлен `app/Core/Env.php`; системные env имеют приоритет |
| Пример конфигурации | ГОТОВО В КОДЕ | `.env.example` с пустыми DB полями |
| Игнорирование секретов и runtime media | ГОТОВО В КОДЕ | Добавлен `.gitignore`; уже отслеживаемые файлы автоматически не удаляются |
| Ротация ранее опубликованного DB пароля | ЗАБЛОКИРОВАНО | Выполняет владелец через панель хостинга; считать секрет скомпрометированным |
| Вывод ошибки при отсутствующей DB конфигурации | ГОТОВО В КОДЕ | Проверка до PDO init, без раскрытия конфигурации |
| CSRF для всех изменяющих POST действий | НЕ НАЧАТО | В текущих маршрутах/контроллерах токены не подтверждены |
| Logout через POST + CSRF | НЕ НАЧАТО | Сейчас logout зарегистрирован GET |
| Проверка доверия X-Forwarded-Proto | ТРЕБУЕТ ПРОВЕРКИ | Auth использует заголовок прокси при определении secure cookie |
| Проверка загрузок, MIME, лимитов и IDOR | ЧАСТИЧНО РЕАЛИЗОВАНО | Нужны целевые негативные тесты |
| Секрет локального хранилища по умолчанию | ТРЕБУЕТ ПРОВЕРКИ | Конфигурация содержит fallback-плейсхолдер; production должен задавать случайный секрет |
| Удаление пользовательских файлов из Git history | ЗАБЛОКИРОВАНО | В storage/media/chat найдены отслеживаемые бинарные вложения. Не удалять без согласования; ограничить доступ/удалить из текущего дерева и истории отдельным решением |
| PHP lint / MySQL integration | ЗАБЛОКИРОВАНО | Нет доступной исполняемой PHP/MySQL среды в GitHub connector |

**Инцидент безопасности:** в публичной истории Git обнаружены реальные DB-реквизиты. Их значение не воспроизводится в документации или логах. Владелец должен немедленно сменить пароль MySQL, проверить журналы доступа и оценить необходимость ротации других секретов. Изменение истории Git не выполнялось.

**Инцидент приватности:** в Git tree присутствуют бинарные файлы под `storage/media/chat/`. Это похоже на пользовательские вложения. Содержимое не раскрывалось. Требуется определить владельца/чувствительность и согласовать удаление из текущей ветки и очистку истории отдельно. `.gitignore` не прекращает отслеживание уже закоммиченных файлов.

## 6. Следующий функциональный пакет

**WEB-0.2 — CSRF-защита и безопасный logout.**

Критерии готовности:
1. Случайный CSRF token хранится в сессии и сравнивается constant-time.
2. Все state-changing POST endpoints требуют токен; исключения явно обоснованы.
3. Токен доступен фронтенду безопасным способом и передаётся в AJAX.
4. Неверный/отсутствующий токен даёт 403 без выполнения операции.
5. Logout только POST.
6. Проверки покрывают валидный, отсутствующий и неверный токен.
7. Не ломаются действующие формы и чат API.
