## 1. Назначение

NAVA Web — самостоятельная веб-подсистема экосистемы NAVA: аккаунты, общение, сообщество, приложения и в перспективе безопасное управление устройствами и синхронизация с Desktop/Mobile. Разработка продолжает существующий PHP/MySQL сайт, без миграции на другой стек и без подключения Desktop к production.

## 2. Архитектура, подтверждённая по исходникам

- PHP-приложение с собственным MVC-подобным разделением Controllers / Models / Core / Views.
- Собственный Router с регистрацией GET/POST маршрутов.
- PDO/MySQL через `app/Core/Database.php`, prepared statements и отключённые emulated prepares.
- PHP Sessions через `app/Core/Auth.php`.
- Маршруты разделены на `app/Routes/web.php` и `app/Routes/api.php`.
- Чат реализован в `ChatController`, моделях Chat/Message/MessageAttachment и API-маршрутах.
- Хранилище вложений имеет локальную реализацию и S3-совместимый сервис; runtime конфигурация расположена в `app/Config/storage.php`.
- Публичная точка входа: `public/index.php`.
- В репозитории также есть игровые ресурсы; их структура и маршрутизация должны оставаться совместимыми.

**Инцидент безопасности:** в публичной истории Git обнаружены реальные DB-реквизиты. Их значение не воспроизводится в документации или логах. Владелец должен немедленно сменить пароль MySQL, проверить журналы доступа и оценить необходимость ротации других секретов. Изменение истории Git не выполнялось.

**Инцидент приватности:** в Git tree присутствуют 5 бинарных файлов под storage/media/chat/ (около 437 KB). Содержимое не раскрывалось; считать пользовательскими вложениями до подтверждения владельца. Кроме того, database_full_fixed.sql содержит INSERT-данные для users, messages, media_objects, media_uploads, chats и других таблиц — это не schema-only dump. Нельзя импортировать его в staging до подтверждения, что строки синтетические, и очистки персональных/чатовых данных. .gitignore не прекращает отслеживание уже закоммиченных файлов.

## 6. Следующий функциональный пакет

**WEB-STAGING-0 — отдельная тестовая онлайн-среда (приоритет по запросу владельца).** Пакет заблокирован до выбора хостинга/создания отдельной тестовой БД. Не подключать production DB, не менять DNS основного домена и не импортировать неочищенный SQL dump. После запуска staging следующим пакетом выполнить WEB-0.2 — CSRF-защита и безопасный logout.

Критерии готовности WEB-0.2:
1. Случайный CSRF token хранится в сессии и сравнивается constant-time.
2. Все state-changing POST endpoints требуют токен; исключения явно обоснованы.
3. Токен доступен фронтенду безопасным способом и передаётся в AJAX.
4. Неверный/отсутствующий токен даёт 403 без выполнения операции.
5. Logout только POST.
6. Проверки покрывают валидный, отсутствующий и неверный токен.
7. Не ломаются действующие формы и чат API.

## 9. Полный анализ реализации и готовности к staging

### Реально работающие по исходникам компоненты

- **Auth:** вход по email/паролю и двухшаговое подтверждение входа; password_verify, ротация session ID при финальном входе, HttpOnly/SameSite cookie. Регистрация и восстановление пароля не реализованы в маршрутах; User::create() сам по себе не является готовым регистрационным сценарием.
- **Profile:** просмотр и редактирование профиля, комментарии, аватар и фон, бейджи/витрины. Изображения сохраняются в публичный каталог public/assets/images; необходимы негативные тесты MIME, XSS и прав доступа.
- **Friends:** текущая страница показывает каталог пользователей, а не реальную систему друзей/заявок.
- **Chat:** личные/групповые чаты, история, отправка/редактирование/удаление, ответы, пересылка, закрепления, mute, typing, online presence, блокировки, создание/выход из групп и вложения. Контроллер проверяет авторизацию и членство/владение сообщением в основных сценариях. История модели ограничена последними 100 сообщениями; курсорная подгрузка старых сообщений не подтверждена.
- **Chat realtime:** WebSocket не реализован; браузер использует polling: сообщения каждые 2 секунды, typing 2.5 секунды, sidebar 7 секунд, online 10 секунд. Это приемлемо для небольшой тестовой группы, но требует нагрузочной оценки на shared hosting.
- **Media storage:** локальное хранилище вне public и S3-compatible driver; подписанные URL, проверки размера/MIME, квоты, дедупликация и ref-count реализованы в коде. End-to-end безопасность и фактическая работа на целевом хостинге не подтверждены.
- **Games:** библиотека, избранное, коллекции, отзывы, достижения, presence/playtime API; игровые статические ресурсы включены в репозиторий.
- **Community:** Gallery, Music и AI страницы сейчас используют статические/случайно перемешиваемые демонстрационные данные; это не готовые пользовательские сервисы и не интеграция с NAVA AI.
- **Navigation:** есть навигация для игр, чата, галереи, музыки, профиля, друзей и AI. Разделы Devices, Applications, Settings и Sync не реализованы.

### Подтверждённые незавершённые/рискованные области

- CSRF отсутствует в просмотренных формах и AJAX; все POST mutations нуждаются в общей защите.
- GET /logout меняет состояние; требуется POST + CSRF.
- Ограничение частоты входа и защита от brute force не подтверждены.
- В Auth не найдено принудительное завершение сессии по idle timeout; last_activity обновляется, но истечение сессии не реализовано.
- X-Forwarded-Proto участвует в решении о Secure cookie без подтверждённого списка доверенных proxy.
- Нет полного тестового покрытия IDOR/XSS/upload edge cases; не делать вывод о полном отсутствии уязвимостей до тестов.
- Четыре SQL-файла имеют разные роли: full fixed schema, games upgrade, repair и media hotfix. Полный dump содержит INSERT-данные; единый проверенный порядок миграций и schema-only staging export ещё не подготовлены.
- 61 PHP-файл найден в tree, включая 13 пустых PHP-файлов/заглушек; vendor/autoload.php пуст, composer.json и package.json отсутствуют. Основные реальные шаблоны находятся в app/Views; app/Services/Views содержит пустые дубликаты/заглушки.
- В репозитории 341 tree entries; публичные файлы занимают около 17.3 MB. Есть пять отслеживаемых бинарных вложений в storage/media/chat/. Их не включать в staging.
- Root .htaccess содержит дополнительные headers/cache rules, а public/.htaccess — в основном rewrite. При выборе DocumentRoot=public/ отдельно проверить, что security headers и запрет листинга реально применяются на хостинге.

### Варианты бесплатного staging

1. **HelioHost Johnny — основной кандидат для первого тестового staging:** бесплатный PHP 8.4/MariaDB, SFTP, scheduled tasks, SSL, около 1 GB storage. Ограничения: нет SLA (цель uptime 97%), свободная регистрация ограничена окнами, нужно входить в аккаунт ежемесячно; свободный план предназначен для development/hobby use. Подходит для небольшого staging, но не считать production-инфраструктурой.
2. **Oracle Cloud Always Free — наиболее гибкий вариант:** до 2 OCPU/12 GB RAM для Ampere A1, 200 GB block volume и MySQL HeatWave Always Free в поддерживаемых регионах. Нужны карта для проверки личности, администрирование Linux, hardening/backup; возможен дефицит ресурсов, а простаивающие VM могут быть reclaimed. Лучше по контролю API/файлов, сложнее в сопровождении.
3. **InfinityFree — не рекомендован для полного NAVA staging:** PHP 8.4/MySQL и 5 GB есть, но индивидуальный лимит файлов 10 MB, cron отключён, SSH/SFTP отсутствует, автоматические API/background requests ограничиваются. Текущие лимиты NAVA Chat (до 250 MB) там не соответствуют реальным возможностям.
4. **Cloudflare Quick Tunnel — только временный preview:** может показать локальный PHP-сайт по временному URL, но компьютер должен оставаться включённым; URL меняется при перезапуске, гарантий uptime нет.
5. **GitHub Actions CI:** поскольку репозиторий публичный, стандартные GitHub-hosted runners бесплатны; можно независимо от staging выполнять php -l и MySQL/MariaDB integration tests.

**Рекомендуемая схема:** GitHub feature/nava-web → бесплатный CI → отдельный HelioHost staging с отдельной тестовой БД → ручная проверка в браузере. Основной домен/DNS и production DB не трогать. Если нужен полный контроль и крупные файлы/API, отдельно рассмотреть Oracle Always Free. До выбора хостинга и создания тестовой БД deployment заблокирован.
